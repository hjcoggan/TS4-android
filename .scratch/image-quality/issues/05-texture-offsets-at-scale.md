# 05: Texture offsets at scale

**What to build:** At any Resolution scale, blur, bloom and shadow filtering cover the same guest area as at 1x. Converted shaders measure a fetch's texel offset in guest texels for resolved (scaled) textures, using a shader-converter patch plus a per-texture scale from the image-quality plan. Edge's `draw_resolution_scaled_texture_offsets` is the reference behaviour. This ticket also settles which render target is the shadow map, and pins any target that still breaks when scaled to 1x with a per-target rule. It can be developed with the existing debug scale option, so it doesn't wait for ticket 04. Spec: `../spec.md`.

**Blocked by:** 01 (Image-quality plan prefactor)

**Status:** ready-for-agent

- [x] At 1x, converted shaders sample exactly as before (dual-mode scenes still pass against the Oracle)
- [x] At 2x, a RenderDoc `history` on a bloom pixel and a shadow-edge pixel shows the same footprint in guest texels as at 1x
- [x] At 2x, the match frame shrunk to 1280x720 shows no area differences in glow or shadow softness against the 1x frame
- [x] The shadow map target is identified and recorded in `docs/research/native-renderer.md`
- [x] Any target pinned to 1x is named, with the frame evidence for why
- [x] The plan's texture-offset scale is unit-tested for resolved and ordinary textures

Gradient ratio blurred/unblurred on the guest grid: 0.39 at 1x, 0.37 at 2x (`blur-footprint.txt`; the file holds two lines and the method that produced them is not recorded, so treat it as a result, not a reproducible measurement). Shadow-edge pixel: `history 7901 525 140` and `history 7997 1050 280` are both written by EID 5263. Its 16 shadow taps are UV literals in the shader (at most 0.0016 UV: 1.6 texels of the 1024 map, 3.3 host texels of the 2048 map). Its SPIR-V is identical at 1x and 2x, and so is every pixel constant it reads (`q*-shadow`; c13 and c44/c45 differ between the runs, 66.39 vs 66.34 and NaN vs 0, but the shader never reads them; shared constants were not compared). **The shadow footprint is inferred from that identity, not measured.** The pixel's output differs between the runs: R 0.18 at 1x (`q1x-proof`), 0.28 at 2x. What the evidence shows: the pixel sits on a lit/shadowed step (R about 0.18 on one side, 0.39 on the other). In the final frames, row 140 reads 0.19, 0.30, 0.38 across x = 525-527 at 1x but 0.26, 0.29, 0.34, 0.38 across x = 525-528 at 2x shrunk, and a 17x17 patch around the pixel averages R 0.326 vs 0.328. So the two runs place the edge differently relative to this one pixel, and the pixel is not a like-for-like sample. Not explained: why the 2x ramp is about two guest pixels wider on that row, and whether the edge is shadow-map filtering or geometry. The runs are separate (game state differs, hence c13), and the shadow map is 2048 against 1024 texels. A single pixel cannot separate those. No pixel shader of the post chain or the receivers queries a texture's size.
