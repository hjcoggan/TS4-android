# 08: MSAA 8x

**What to build:** An 8x choice for the MSAA setting. The game's alpha-to-mask shader patch is extended to an 8-sample case, so alpha-masked surfaces keep their look at 8x. Spec: `../spec.md`.

**Blocked by:** 07 (MSAA 4x)

**Status:** ready-for-agent

- [x] 8x is accepted in the settings file and on the command line
- [x] At 8x, the match pass renders at 8 samples on a device that supports it, and falls back on one that doesn't
- [x] Academy foliage at 8x matches its look at Original (no holes or solid quads)
- [x] The match frame at 8x is compared with the Original frame of the same run: only edge differences

## Comments

- 2026-10-27 (Claude): Patch `0008-alpha-to-mask-8x` and `ts4_msaa=8` in the plan were already in (af95d5b); the shader pack in `cache/` was converted with it (every HLSL file has the `samples == 8` case). Fixed here: the device's sample counts (`DeviceLimits::sample_counts`) took only the framebuffer limits, but render targets are also sampled (`VK_IMAGE_USAGE_SAMPLED_BIT`, resolves), so they now also need `sampledImageColorSampleCounts`, `sampledImageDepthSampleCounts` and `sampledImageStencilSampleCounts` (no target has storage usage). That rule is `image_quality::TargetSampleCounts` (pure, unit-tested); `LimitsOf` feeds it the Vulkan limits. New debug cvar `ts4_native_debug_max_samples` (0 = the GPU's own) treats counts above it as unsupported. Native now logs `render targets can have 1, 2, 4, 8 samples` at start, and `MSAA 8x is not supported for render targets on this GPU; using 4x` once when the setting falls back on a multisampled target. Build and `pwsh scripts/build.ps1 -Action Check` pass (274 test cases, 23369 assertions; pytest 88; launcher 53).
