# 03: Themed Launcher

**What to build:** The Launcher's pages draw the disc art. Home: the background under a dark scrim, the logo in place of the title text, the box art beside PLAY. Setup and Settings: the background more subdued, the logo small in the header. The window and taskbar icon is the title icon, and the Direct shortcut points its icon at the `.ico` in the art folder. Accent colours are retuned to the art. Each image that is missing falls back to the original look's resource, with the same layout. A small footer line says this is a fan recompilation, not affiliated with 2K Sports or 2K Czech, and that the art comes from the player's disc. Text keeps 4.5:1 contrast against what lies under it. Spec: `.scratch/launcher-look/spec.md` (Solution, "Theme reads the art", "Readability").

**Blocked by:** 02 (Disc art module); `.scratch/launcher-ux/issues/06-starting-the-game.md` (the Direct shortcut) and `07-controller-and-accessibility-pass.md` (the final page layout)

**Status:** resolved

- [x] Launcher.Tests: with a full art folder the theme resources point at the art; with an empty or partial one each missing image falls back to the original resource
- [x] Launcher.Tests: the shortcut writer sets the icon to the art folder's `.ico` when it exists, and to the exe otherwise
- [x] The published Launcher holds no game art: no image in `out/launcher/publish-app` or the repo comes from the disc
- [x] `pwsh scripts/build.ps1 -Action Check` passes

### Review fixes

2026-10-28, after the code review of `815cfac...launcher-look`:

- A second disc that writes the same file names is a different look: `LauncherTheme.ArtStamp` (the art folder's `DiscArtFolder.Stamp`) is part of `SameLookAs`, and `MainWindow.ReloadTheme` reloads when the folder's stamp is not the theme's. The test failed against the old `SameLookAs` first.
- `LauncherTheme` is the one place that decides. `LauncherTheme.From(art, canDraw)` counts a picture the window cannot draw as missing and takes the palette and credit line from what is left; `LookFor(page)` gives the page's background, whether it is dimmed and whether the header is the logo (and its height). `MainWindow` only loads the files it is asked about and applies the answer. Avalonia.Headless is in the package cache but is not a Launcher.Tests dependency (the screenshots came from a scratch harness), so the decision lives in Core and is tested there with a fake `canDraw`; the App side is a mapping.
- `ThemeImage` is gone: the theme names pictures by Disc art slot (`Source(DiscArtSlot)`; for `TitleIcon` it is the `.ico`).
- Brush keys say what they hold: `AccentBrush`, `AccentHotBrush`, `SecondaryBrush`, `SilverBrush` (were Ball, BallHot, Court, Sky). The list lives in `ThemePalette.Brushes()`; tests hold `Theme.axaml` to it (same keys, the original palette's colours) and that no page names a brush it does not declare.
- The original look is unchanged before a disc: the disabled PLAY has its original fixed colours (`#4A4E2A` fill, `#2A2A2A` text) from `AccentDisabledBrush` and `OnAccentDisabledBrush`; the art palette has its own (`#4A2A2E`, `#D2C6CA`, above 4.5:1, tested). `LauncherLook` logs with the `Disc art:` prefix.
- `MainWindow` no longer re-reads the art on every activation (it only refreshes); the look reloads when the disc row accepts or setup ends (the `_themeKey` in `Refresh`) and after the start-up restore.
- Screenshots (offscreen Avalonia headless with Skia, never a window; scratch harness, not kept) in `analysis/launcher-look/`, the earlier set moved to `before-review-fixes/`: `art-1-setup`, `art-2-home` (the real Home: prepared files from `%LOCALAPPDATA%/TopSpin4Recomp` read only, a stub exe, PLAY enabled, "Ready to play."), `art-2b-home-disabled`, `art-3-settings`, `art-4-settings-small`, and `original-*` the same (`original-2-home` is the original look with PLAY enabled; `original-2b-home-disabled` shows the original disabled PLAY). Settings reads "unavailable" because no game exe is run.
- `pwsh scripts/build.ps1 -Action Check` passed: pytest 110, host tests 403 cases, Launcher.Tests 384 passed, 1 skipped. The smoke run could not run from the worktree (no built `topspin4.exe`, no game data); nothing in the game's C++, patches or flags changed.
