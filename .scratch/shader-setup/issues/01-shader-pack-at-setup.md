# 01: Shader pack prepared at setup

**What to build:** The Launcher's setup ends with a complete shader pack in the cache folder, as `.scratch/shader-setup/spec.md` ("Prepare shaders") describes, so a fresh install's Native renderer never skips a draw for a missing shader.

- **Archive reader (Launcher.Core):** every single-part entry of the prepared game folder's `.arc` archives, decoded with the vendored managed LZX decoder, kept when it is a valid container (magic `0x102A1100`/`0x102A1101`, header size + microcode size = entry length), named `ps_`/`vs_` + FNV-1a-64 as the game's dump names it, deduplicated. Layout: spec, "Implementation Decisions". If the vendored decoder cannot read the frames, stop and ask the owner before adding libmspack.
- **Module shaders (game exe):** a headless mode next to `--ts4_prepare_pipelines` that loads Loader and Swing as play does (TU1 applied), writes every valid container in their read-only data into the shader top-up folder under its dump name, prints a result line and exits. If the runtime cannot load the Modules without running guest code, record what blocks it in Comments and ask; do not reverse-engineer around it.
- **Conversion and pack:** copy WWE All Stars' converter interface, `XenosRecompConverter`, `ShaderPackFile` (build and check) and `ShaderPreparation` (ADR-0004), adapted to Top Spin 4's names. Converter id from the XenosRecomp patch series at build time, as the game computes it. XenosRecomp ships in the release's `xenosrecomp/` folder, where the game already looks for it.
- **Setup:** a "Preparing shaders" band in setup's overall progress after the disc and TU1 bands; "prepared" requires a usable pack; cancel and resume; a failure is shown and Play stays available (Native falls back to Classic as today without a pack). A stale pack (other converter id) is rebuilt before the next Play without a click; Repair rebuilds it. The space check counts the pack. Launcher.Cli runs the same step with text progress.

**What was built.** Launcher.Core: `ShaderContainer`, `ArchiveShaders` (the `.arc` reader on the vendored LZX decoder), `ShaderPackFile`, `ShaderPreparation`, `XenosRecompConverter` (copied from WWE, ADR-0004), `GameModuleShaders` + `PrepareRunner`, converter id generated by `Launcher.Core.csproj` from `patches/xenosrecomp/*.patch` (value `0x99bb4eadf986e368`, equal to the id in the owner's existing `cache/topspin4.shaderpack` header). Setup: `SetupFlow` shaders band (`SetupStep.PreparingShaders`, `OverallProgress`), `WantsShaderRebuild` (stale or damaged pack, the window rebuilds at open without a click), `Repair()` (model only: there is no Repair button in this Launcher yet), `ShaderFailure` (shown on Home, Play stays available). Space check: `Preparation.SpareBytes` now includes `ShaderPackBytes`. `topspin4-setup` runs the same step (`--game-exe`, `--xenosrecomp` for developers). Game: `--ts4_prepare_modules` (`src/module_shaders.{h,cpp}`, hooked in `OnPreLaunchModule`): `LoadUserModule(path, call_entry=false)` for Loader and Swing, scan of their non-code sections, containers written through `ShaderTopUp`. `scripts/scene_runner.py --install DIR` (folders of a fresh install). Glossary: Shader pack, Top-up.

**Neither stop-and-ask condition fired.** The vendored LZX decoder reads the archives' frames (no libmspack). `LoadUserModule` with `call_entry=false` loads both Modules (TU1 applied) without guest code.

**One thing the ticket did not foresee: XenosRecomp cannot convert 64 of the 1099 containers.** All 64 are vertex shaders from the Modules' data (the top-up folder lost exactly 64 of its 92 files, 28 remain); the 1007 archive shaders all convert. The whole-folder run exits 2 or crashes (0xC0000409) and writes no cache. Found by converting each container alone (not a game run). Causes seen: 22 of them use registers past r31 (`printedRegisters[32]` and the `i < 32` register declaration in `shader_recompiler.cpp`; a pixel interpolator in a high register would also overrun that array), and the rest fetch with `tfetchPosition(..., iPosition0, ...)`, an input the vertex declaration code leaves undeclared. A trial patch raising the register count to 128 cut the failures from 64 to 55 and was reverted (it changes the converter id, so every dev pack goes stale, and the other 55 need converter work). So `ShaderPreparation` now tolerates it: when the whole set fails it tries each container alone (parallel processes), drops the ones that fail and converts the rest together, and reports the dropped names (setup log, `topspin4-setup` output). A converter that cannot start, or fails on more than half, still fails the step. Whether those 64 matter in play is open: the e2e match run below drew with none of them.
