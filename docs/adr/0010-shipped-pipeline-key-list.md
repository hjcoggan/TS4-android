# A pipeline key list ships with the game

Setup prepares the Native pipelines before the first Play (`--ts4_prepare_pipelines`), but it can only plan pipelines for keys it knows. A fresh install has no store of its own, so without a list every pipeline compiled or fast-linked on first use, during play. `data/pipeline-keys.txt` is committed and ships beside the game exe as `pipeline-keys.txt`, as WWE All Stars does (its ADR-0019, copied under ADR-0004). It holds plain `PipelineKey`s only: shader container hashes, formats and render-state values, one hex line each, with no shader code and no game data, so ADR-0006 still holds. The Launcher hashes the file, so a build that ships a new list prepares again on the next Play.

`scripts/pipeline_keys.py merge` builds the list from session stores (`cache/native-pipelines/keys.bin`) and is idempotent; one Native run of each scene in `tests/scenes/` makes the base, and the owner's hand sessions add what scripted runs miss. The key size comes from the stores and the list, not from the script, and a host test checks the shipped list against this build's `sizeof(PipelineKey)` and converter id. `build.ps1 -Action Build` runs `pipeline_keys.py check` against the dev shader pack.

A key holds the render target's sample count, so the MSAA setting changes keys: the list holds only keys at the default (`ts4_msaa = "original"`, 1 or 2 samples), and stores recorded with MSAA raised are filtered to those before the merge. Prebuild does not choose keys by the current setting, so 4x and 8x keys would cost every player time; prebuilding them for raised MSAA is left open.

A XenosRecomp patch change gives a new converter id, and the game then drops the whole list (`prebuild_plan.cpp`). A patch that keeps every key's meaning (it only adds what no listed key uses) moves the list with `pipeline_keys.py retag`; any other patch change, or a change to `PipelineKey`, needs the list merged again from new stores. The list needs a merge before each release.
